## 3. E3 — 嵌入模型的多语能力（最关键的一组）

**问题**：中英混合语料下，单语模型与多语模型的差距有多大？

用同一份 `data/queries.txt`（其中多条是"中文问、英文文献"的跨语言检索）对比：

| 嵌入模型 | 维度 | 大小 | Recall@1 | Recall@3 | 跨语种命中 |
|---|---|---|---|---|---|
| `intfloat/multilingual-e5-small`（默认） | 384 | 470MB | | | |
| `BAAI/bge-small-zh-v1.5` | 512 | 95MB | | | |
| `sentence-transformers/all-MiniLM-L6-v2` | 384 | 90MB | | | |

```bash
# 通过 --embedder 参数或直接改 config.EMBED_MODEL 切换
python src/agent.py --embedder bert index
```

**已有一个前置证据**：本地用**字面匹配的哈希编码器**跑同一批问题（无跨语言能力），
结果是**同语种问题 3/3 命中、跨语种问题 0/3 命中**。这说明跨语言检索能力不能靠字面重合获得，
必须由多语嵌入模型提供 —— E3 就是把这个结论量化。

**预期**：两个单语模型在跨语种问题上显著掉点；e5-small 在两类问题上都可用。

## 4. E4 — 有 RAG vs 无 RAG

**问题**：检索真的有用吗？还是模型自己就知道？

新增一个 `--no-context` 模式（或直接手工把 prompt 里的【资料】置空）后对比：

| 设置 | 事实正确率 | 数值正确率 | 拒答正确率 | 是否出现编造 |
|---|---|---|---|---|
| 无资料（纯模型） | | | | |
| 摘要级 RAG | | | | |
| 全文级 RAG | | | | |

**预期**：无资料时模型会编造具体数字（尤其问"某篇论文提升了多少"）；全文 RAG 能给出
带章节页码的准确引用。这一组的价值最高 —— 它直接证明项目存在的必要性。

## 6. 结论模板（跑完填这一段）

> 在 AMD Radeon 8060S（共享 64GB、实测带宽 ___ GB/s）上，1.5B 模型 bf16 解码达到
> ___ tok/s，约为理论上限 ___ tok/s 的 ___%，说明**解码瓶颈是内存带宽而非算力**。
> 检索侧成本随库规模线性增长但绝对值极小（___ 篇 / ___ chunk 仅占 ___ KiB）；
> 生成侧成本只与模型大小和上下文长度有关。因此算力投资应优先投向
> **更高带宽与更高并发**，而不是更大的向量库。
